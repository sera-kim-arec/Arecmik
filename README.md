# Arecmik

WORK와 LIFE를 나누어 일정과 할 일을 관리하고, 나의 기록을 모으는 개인 다이어리입니다.

- **홈**: 일정·할 일 확인, 오늘의 일지/일기, 빠른 기록 남기기
- **프로젝트**: 할 일·현황·비용과 관련 기록을 함께 확인
- **기록 → 모아보기**: 일지·글·메모·완료한 일·지난 일정·지출·자료를 날짜별로 확인하고 종류·월·프로젝트로 필터링
- **검색**: 현재 공간 안의 기록·메모·할 일·프로젝트·지출·자료·피드백 검색

기록에 프로젝트를 선택하면 프로젝트에서도 같은 기록을 열 수 있습니다. 기존 글은 복사 없이 연결할 수 있고, 프로젝트에서 새 글을 쓰면 프로젝트가 자동으로 연결됩니다.

공간 정보가 없던 기존 자료는 WORK에 표시됩니다. 자료를 열어 **공간**을 바꾸면 LIFE로 옮길 수 있습니다. 보관함은 기존 데이터를 삭제하거나 일괄 변환하지 않습니다.

## 로컬 실행

별도 빌드나 패키지 설치가 필요 없는 정적 웹 앱입니다. 저장소 디렉터리에서 실행하세요.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

실제 사용은 Firebase JavaScript SDK, Google 로그인, Firestore에 접근할 수 있는 네트워크와 Firebase에 등록된 호스팅 도메인이 필요합니다. Firebase 클라이언트 설정은 `index.html`에 있습니다.

## 브라우저 테스트

Python Playwright와 `/usr/bin/chromium`이 설치된 환경에서 실행합니다.

```sh
python3 -m unittest discover -s tests -v
```

테스트는 실제 앱을 Chromium에서 열고 Firebase를 메모리 기반 테스트 어댑터로 대체합니다. WORK/LIFE 분리, 기록 입력·수정, 프로젝트 연결, 검색, 자료 이동, 필터·페이지 확장, 모바일 너비, 저장 실패 시 내용 유지와 HTML 이스케이프를 검증합니다. 실제 계정으로 로그인하거나 실제 Firebase 데이터를 읽고 쓰지 않습니다. Google 로그인과 기기 간 동기화는 별도의 실제 환경 확인이 필요합니다.

## 저장과 복구

- 글·일지·프로젝트 메모의 편집은 전송 전에 사용자별로 이 기기에 임시 보관합니다. 화면 상단에서 저장 상태를 확인할 수 있습니다.
- 전송이 끝나기 전에 새로고침했거나 저장에 실패하면 **임시 편집 보기**에서 확인하고 복구본을 새 글로 보관할 수 있습니다. 다른 기기에서 수정한 원본을 자동으로 덮어쓰지 않습니다.
- **기록 남기기** 창을 닫거나 새로고침해도 같은 공간에서 다시 열면 임시 내용을 복구합니다. 서버 저장이 완료되면 해당 임시 내용을 정리합니다.
- 임시 내용은 작성한 브라우저에 보관되므로, 전송 전에는 다른 기기에서 보이지 않습니다. 브라우저 저장 공간을 삭제하면 임시 내용도 삭제됩니다. 앱의 오프라인 최초 실행을 보장하는 기능은 아닙니다.
- 금액은 상품명·수량과 구분하고 천 단위 쉼표를 지원합니다. 여러 금액은 줄바꿈 또는 쉼표 뒤 공백으로 구분합니다. 모호한 금액이나 존재하지 않는 날짜는 저장하지 않습니다.
- 할 일·비용 편집은 저장 실패 시 창과 입력 내용을 유지합니다. 백업은 모든 데이터 종류를 읽은 경우에만 생성하며, `complete`와 종류별 `counts`를 포함합니다.

배포 버전은 설정 메뉴 하단에서 확인할 수 있습니다.

## 폴더와 업체·항목 정리

- **기록 → 글 → 폴더 관리 → 삭제**에서 폴더를 삭제할 수 있습니다. 안의 글과 하위 폴더는 상위 폴더로 옮기며, 최상위 폴더라면 폴더 밖으로 옮깁니다.
- 프로젝트 **현황**의 업체·항목은 펼치지 않고도 제목 옆 **삭제**를 누를 수 있습니다. 연결된 할 일·지출은 유지하고 업체·항목과의 연결만 해제합니다.
- 삭제와 연결 해제는 함께 저장하며, 실패하면 변경하지 않습니다. **되돌리기** 또는 **설정 → 휴지통**에서 복구할 수 있습니다. 삭제 후 다른 곳으로 옮긴 기록의 연결을 복구로 덮어쓰지 않습니다.
- 비용 분류 이름 변경을 취소하면 기존 이름을 유지합니다. 과거 잘못 저장된 `false` 같은 분류 값은 화면에서 유효한 분류 이름으로 사용하지 않으며 금액·날짜·내용은 유지합니다.

## 프로젝트 메모

- **핵심 메모**에는 자주 확인할 요약을 적습니다. 기존 프로젝트 전체 메모도 이곳에 그대로 표시됩니다.
- **진행 기록**에는 상담 내용, 결정한 이유, 바뀐 내용을 날짜별로 남깁니다. 최근 12개부터 표시하고, 더 보기와 접기를 지원합니다.
- 진행 기록의 **핵심 고정**을 누르면 같은 원본이 핵심 메모 아래에도 표시됩니다. 고정된 내용을 눌러 원본을 수정할 수 있고, 고정 해제 후에도 진행 기록은 남습니다.
- 한 줄 진행 기록은 텍스트와 선택한 날짜를 이 기기에 임시 보관합니다. 저장 실패 시 입력을 유지하고, 서버 저장이 끝난 뒤 비웁니다.
- 날짜별 기록의 수정도 자동저장 상태 및 **임시 편집 보기**에서 확인하고 복구할 수 있습니다. 기록 삭제는 휴지통 보관과 함께 처리하며, 실패하면 원본을 유지합니다.

## 시간 없는 일정

달력의 **＋ → 일정**에서 날짜와 제목만 입력해도 종일 일정으로 저장됩니다. 시간은 선택 사항이며 오전 9시를 자동으로 넣지 않습니다. 프로젝트의 일정 입력도 같은 방식으로 사용할 수 있습니다.

기존 일정을 열어 **시간 빼기**를 눌러도 일정 구분을 유지합니다. 할 일로 바꾸려면 수정창의 **구분**에서 직접 선택합니다. 날짜만 있는 일정에도 나중에 시간을 추가할 수 있습니다.

## 달력에서 기간 일정 만들기

- PC에서는 월·주간 달력의 **빈 날짜 칸을 시작일부터 끝날짜까지 드래그**합니다. 선택한 마지막 날도 일정에 포함됩니다. 반대 방향으로 끌어도 날짜순으로 정리합니다.
- 모바일에서는 **빈 날짜 칸을 길게 누른 뒤 끌어서** 기간을 고릅니다. 길게 누르지 않고 쓸어 올리면 평소처럼 화면을 스크롤합니다.
- 손을 놓으면 시작 날짜와 끝 날짜가 채워진 **일정** 입력창이 열립니다. 제목을 입력하고 저장하면 여러 날짜에 걸친 하나의 일정으로 표시됩니다. 시간은 선택 사항입니다.
- 입력창에서 시작일·종료일을 직접 바꿀 수 있습니다. 종료일이 시작일보다 빠르면 입력을 유지하고 안내합니다.
- Esc를 누르거나 달력 밖에서 놓으면 기간 선택을 취소합니다. 기존 일정은 드래그로 날짜를 옮길 수 있고 기간 길이도 유지됩니다.
- 달력 입력창은 서버 저장이 끝난 뒤 닫힙니다. 실패하면 제목·기간·프로젝트를 유지하고 재시도할 수 있으며, 저장 중 중복 제출을 막습니다.

## 안드로이드 월 달력 위젯

[설치 안내](https://sera-kim-arec.github.io/Arecmik/widget.html)에서 개인 설치용 APK를 받을 수 있습니다. 월 달력 아래에 선택한 날짜의 일정·할 일을 표시하고, 위젯에서 완료 체크와 WORK/LIFE 전환을 지원합니다. 웹앱 설정 메뉴에서도 설치 안내를 열 수 있습니다.

APK 설치 후 기존 Google 계정을 브라우저에서 연결하고 홈 화면에 위젯을 추가합니다. 시간 없는 일정과 여러 날 일정도 표시하며, 완료 변경은 원본에 반영합니다. 별도 유료 서버는 추가하지 않고 기존 Firebase의 무료 한도가 적용됩니다. 자동 동기화는 약 1시간 간격이고 Android 절전 정책에 따라 지연될 수 있습니다. 설정의 **APK 설치 · 업데이트**에서 v1.2.1로 업데이트하면 JSON 백업 파일 선택과 반복 완료 취소의 보완 사항이 적용됩니다.

네이티브 소스·검증·서명·연결 방식은 [android/README.md](android/README.md)에 설명되어 있습니다.

## 앱 테마

**⚙ → 앱 테마**에서 레몬 크림·흑백을 선택합니다. 기본값은 레몬 크림이며, 기존 반투명 설정도 레몬 크림으로 전환합니다. 선택 즉시 카드·달력·입력창의 색감이 바뀌며 현재 브라우저에 저장합니다. Android 위젯 테마와는 독립적이며 기기 간 동기화나 Firebase 읽기·쓰기는 발생하지 않습니다.

초기 HTML 표시 전에 `app-theme.js`가 저장된 테마를 적용해 새로고침 시 색상이 뒤늦게 바뀌는 현상을 줄입니다. 테마 선택은 CSS 변수와 선택 UI만 바꾸며, 작성 중인 글·입력값이나 사용자가 지정한 프로젝트 색상을 변경하지 않습니다.

## 사용성 보완 · 2026.10.16.8

- 빠른 할 일 입력은 서버 저장을 확인한 뒤 비웁니다. 실패하면 입력을 유지하며, 빠른 입력과 일정·자료·비용 편집의 초안은 사용자별로 이 기기에 보관합니다.
- 완료 체크는 전송 중 표시 후 성공을 확정합니다. 실패하면 원래 상태를 유지하고 재시도할 수 있습니다. 반복 완료·다음 회차 생성과 취소는 함께 처리하며, 다음 회차를 수정했다면 자동 취소로 지우지 않습니다.
- 프로젝트 삭제는 기록·글·할 일·지출의 연결 해제와 함께 저장합니다. 복구는 이후 바꾼 연결과 이미 존재하는 원본을 덮어쓰지 않습니다.
- 브라우저·설치형 웹앱·Android 앱에서 같은 탐색 이력을 사용합니다. 프로젝트와 검색에서 연 글은 이전 화면·검색어·보관함 필터·스크롤 위치로 돌아옵니다.
- 최초 자료 조회가 실패하면 오류 설명과 **다시 불러오기**를 표시합니다. 검색 결과 없음에는 검색어 지우기와 다른 공간에서 찾기를 제공합니다.
- 모바일 월 달력의 높이를 줄이고 선택일 **일정 추가**를 제공합니다. 할 일 완료 버튼의 터치 영역은 44px로 넓혔으며, 모바일 삭제·하위 항목 관리는 상세 편집창에서 이용합니다. 프로젝트는 할 일을 먼저 보여주고 관련 기록은 최근 6개부터 종류·월 필터와 더 보기로 탐색합니다.
- 기록 작성창에서 **핵심 기록으로 고정**을 선택할 수 있습니다. 프로젝트를 선택한 고정 기록은 해당 프로젝트의 핵심 메모에도 표시합니다.

## 백업 가져오기

**설정 → 백업 가져오기**에서 Arecmik의 전체 백업 JSON을 선택합니다. 파일의 전체 여부·건수·중복 번호를 검증한 후 추가할 기록을 미리 보여 줍니다. **현재 앱에 없는 기록만 추가**하며 기존 내용을 덮어쓰지 않습니다. 현재 기록을 과거 내용으로 교체하는 기능은 아닙니다.

사진을 포함한 모든 종류를 가져옵니다. 큰 백업은 여러 트랜잭션으로 나눠 처리하므로 도중에 실패하면 일부 묶음이 이미 반영될 수 있습니다. 같은 파일을 다시 선택하면 반영된 기록을 건너뛰고 이어갈 수 있습니다. Android 앱에서 파일을 선택하려면 v1.2.1 이상이 필요합니다.

검증 내용과 실기기 확인 항목은 [UX·QA 수정 내역](docs/ux-qa-2026-10-16.md)에 정리했습니다.
