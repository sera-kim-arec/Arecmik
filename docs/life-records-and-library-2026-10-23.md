# LIFE 기록과 자료실

버전: `2026.10.23.7`

LIFE의 일기·독서 감상·영화 감상은 자신의 경험을 돌아보는 기록이다. 다시 읽을 글·인사이트·참고 링크는 꺼내 쓰는 자료로 보관한다. 자료실은 WORK와 LIFE에 각각 두고 기존 공통 폴더·검색을 유지한다.

## 화면과 작성 흐름

- LIFE 모아보기의 이름을 ‘나의 기록’, LIFE 일지를 ‘일기’, 양쪽 공간의 자료 분류를 ‘자료실’로 표시한다. 기본 기록 모음에 자료나 할 일을 자동으로 넣지 않는 기존 동작을 유지한다.
- 자료실을 선택하면 주 작성 버튼이 ‘자료 보관’으로 바뀐다. 다른 작성 방식 메뉴에서 기록·일기·긴 글도 계속 작성할 수 있다. 자료가 없는 화면에서도 자료 보관을 바로 시작할 수 있다.
- LIFE 기록 작성과 긴 글에 ‘일상 / 독서 / 영화 / 기타’ 종류 선택을 추가한다. 기본은 ‘분류 없이 기록’이며 필수 입력을 늘리지 않는다. 저자·감독·평점 입력을 요구하지 않는다.
- LIFE의 기존 날짜·프로젝트 필터에 기록 종류를 함께 둔다. 일상·독서·영화·기타·분류 없는 기록을 선택해 찾을 수 있고, 긴 글과 짧은 기록을 함께 찾는다. 일기는 일상 종류로 조회한다.
- 기록 목록·전체 검색·폴더 목록에 독서·영화 등의 종류를 표시한다. ‘독서’, ‘영화 기록’ 등으로도 검색할 수 있다.
- 자료 작성 안내는 LIFE의 다시 읽을 글·인사이트·참고 링크, WORK의 다시 쓸 정보·링크·문구에 맞춘다.

## 보존과 호환성

선택한 종류는 기존 `moms` 또는 `notes` 원본의 선택 필드 `recordType`에 저장한다. 분류를 만들기 위해 자료를 복제하거나 기존 기록을 추측해서 이동하지 않는다. 종류가 없는 기존 기록은 분류 없는 상태로 조회·편집할 수 있다. 기존 일기 문서의 분류 필드를 일괄 수정하지 않는다.

기록 종류도 기존 트랜잭션 충돌 검사와 임시 저장에 포함한다. 본문만 고칠 때 다른 기기에서 바꾼 종류를 보존하고, 종류를 동시에 다르게 고치면 기존 충돌 안내로 멈춘다. 긴 글의 종류는 기존 안전한 자동 저장과 실패 복구 흐름을 사용한다. 이전 버전의 임시 작성 내용에 종류 필드가 없어도 이미 저장된 종류를 지우지 않는다.

종류 필터는 LIFE에만 노출한다. 자료실·지출·할 일 등 다른 분류로 전환하거나 조건을 지우면 종류 조건을 해제한다. 새 기록을 저장하면 다른 필터 뒤에 숨지 않도록 기존 새 항목 표시 동작을 따른다. 이미 작성 중인 임시 내용이 있으면 그때 선택한 종류를 현재 필터보다 우선한다.

검증은 모의 Firebase로 실행하며 실제 사용자 데이터에 접근하지 않는다. `tests/test_life_records.py`는 감상 기록 생성·조회, 기존 기록 보존, 자료실 작성, 필터와 WORK 분리, 임시 저장·실패·충돌, 긴 글 자동 저장, 이전 임시 내용 호환, 320/390/1365px 화면을 확인한다.

새 LIFE 검사 9개를 포함한 333개 전체 회귀 검사를 실행했다. 새로고침 직후 작성 버튼의 종류를 판단하기 전에 화면이 준비되기를 기다리도록 테스트 도우미를 보완했다. 이후 3개 프로세스로 분할 실행한 105개·84개 검사는 모두 통과했고, 144개 검사에서는 기존 중첩 문단 드래그 1건만 병렬 부하에서 실패했다. 같은 코드의 앞선 직렬 실행에서는 통과한 항목이며, 해당 파일의 드래그 검사 14개를 단독 재실행해 모두 통과했다. 편집기 코드는 이 변경에서 수정하지 않았다.

추가 화면 점검에서 LIFE 기록·독서 필터·작성창·자료실의 320/390/1365px 화면과 `/Arecmik/` 경로의 320~1920px 주요 탭에 가로 넘침이 없음을 확인했다. 미리보기는 실제 저장소와 분리되며 새로고침 시 예시 작성 내용이 초기화된다.
