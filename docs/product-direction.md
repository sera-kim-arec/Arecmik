# Arecmik의 제품 방향과 사용자 선호

대화에서 확인한 기준을 이어서 작업할 수 있도록 정리한 문서다. 기준일: 2026-10-26. 고정된 사양이 아니며 이후 사용자의 요청에 맞춰 갱신한다.

## 만들고 싶은 앱

**일과 생활을 한곳에 내려놓고, 필요할 때 믿고 꺼내 보는 나만의 작업실.**

사용자가 반복해서 말한 기준은 “직관적이고, 한눈에 들어오고, 차분하고 정돈되어 있고, 작성하기 귀찮지 않으며, 실제로 도움이 되는 앱”이다. 써두면 안심되고 다시 찾을 때 믿을 수 있어야 한다.

변경할 때 다음을 기준으로 판단한다.

1. 사용자가 기억하고 있어야 할 일을 줄이는가?
2. 필요한 정보를 찾아다니는 수고를 줄이는가?
3. 적고 저장하고 다시 이어 쓰기 편한가?

## 사용 환경과 우선순위

- 개인이 혼자 사용하는 앱이며 무료로 계속 사용할 수 있어야 한다. 기존 GitHub Pages·Firebase와 외부 서비스의 제약을 고려한다.
- WORK는 PC 사용이 많다. 빠른 검색, 정보의 재사용, 놓친 할 일과 다음 행동 확인이 중요하다.
- LIFE는 안드로이드에서도 사용한다. 일정·할 일과 함께 일기, 독서·영화 감상, 생활 기록과 스크랩을 남긴다.
- WORK와 LIFE의 구분을 유지한다. 회사 할 일 화면에 지출 기능을 불필요하게 드러내지 않는다.
- 월 달력으로 일정을 보는 것을 선호한다. 기존 모바일 앱·월 달력 위젯 흐름도 고려한다.

## 각 공간의 역할

| 공간 | 담는 것과 다시 여는 이유 | 정리 중심 |
| --- | --- | --- |
| 일정·할 일 | 앞으로 해야 할 행동과 약속 | 날짜·완료·다음 행동 |
| 기록 | 내가 겪고 생각하고 결정한 것. “그때 어땠지?” 하고 돌아보기 | 날짜·경험·프로젝트의 흐름 |
| 자료실 | 다시 꺼내 쓸 정보. “그 정보 어디 있지?” 하고 찾아 활용하기 | 주제·폴더·검색·즐겨찾기 |
| 프로젝트 | 하나의 일을 진행하는 데 필요한 할 일·현황·메모·기록·자료 | 진행 상황과 관련된 원본 |

면접 일정은 달력, 면접 진행 회고는 기록, 다음에도 사용할 면접 질문지는 자료실이다. 책을 읽은 감상은 기록이고 재사용할 인용문은 자료가 될 수 있다. 직접 작성한 매뉴얼도 자료다. 글·링크 같은 작성 형식으로 용도를 구분하지 않는다.

폴더는 기록·자료실 안에서 정리하는 도구다. 별도 정리함을 세 번째 보관 장소처럼 만들지 않는다. 폴더·상세·홈 목록에서도 선택한 보관 용도의 구분이 유지되어야 한다. 하위 폴더는 부모 아래에 들어가 보이고, 현재 위치와 부모로 돌아가는 길이 분명해야 한다.

## 작성과 정보 연결

- 기록과 자료는 편안한 공통 글쓰기 도구를 사용한다. 노션처럼 문단·토글·이미지를 자연스럽게 작성·삭제·이동할 수 있는 동작이 중요하다. 겉모양만 비슷한 기능으로 충족되었다고 판단하지 않는다.
- 어디서 쓰기 시작했는지에 따라 보관 용도와 폴더를 기본으로 정한다. 종류·폴더 등의 분류는 적은 수의 선택 사항으로 둔다.
- 일정에서 메모하고, 프로젝트에서 관련 기록·자료를 열고, 검색으로 원본을 찾는 흐름을 이어준다. 같은 내용을 여러 곳에 복사해 관리하지 않게 한다.
- 연결은 상세 화면에서 필요할 때 확인한다. 목록의 모든 항목에 연결 버튼과 큰 행동 버튼을 반복하지 않는다.
- 할 일과 완료 항목을 기본 기록 목록에 모두 누적하지 않는다. 사용자가 남긴 내용이 기록의 중심이다.
- 기존 원본·사진·프로젝트·연결과 작성 중 내용을 보존한다. 저장 실패·뒤로 가기·다른 기기 수정에도 내용을 잃지 않는 신뢰가 중요하다.
- 앱과 노션 두 곳을 동시에 관리하도록 만드는 흐름을 원하지 않는다. 노션의 편안한 글쓰기와 한곳에서 관리하는 경험이 요구의 핵심이다.

## 디자인과 변경 방식

- 차분하고 정돈된 바탕에 기존의 귀여운 레몬을 포인트로 사용한다. 레몬을 좋아하지만 못생긴 대체 아이콘, 과한 장식과 강한 초록색은 선호하지 않는다.
- PC에서는 적절한 정보 밀도와 빠른 탐색을, 모바일에서는 읽기 쉬운 글자와 편한 터치를 우선한다.
- 큰 카드·버튼, 과도한 빈 공간, 반복 안내 문구, 중복 분류를 줄인다. 설명보다 실제 제목·개수·날짜·상태가 보여야 한다.
- 앱 전체를 자주 재배치하기보다 현재 사용하는 흐름 안에서 문제를 고친다. 특히 WORK 월 달력 홈의 익숙한 배치를 존중한다.
- 필요한 수정을 설명과 미리보기에만 머물지 않고 실제 사용 흐름까지 완성하는 것을 선호한다. 사용자의 최신 요청과 이미 합의한 범위에 맞춰 진행한다.
