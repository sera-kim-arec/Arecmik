# 글과 자료의 공통 폴더

배포 버전: `2026.10.23.6`

자료가 글과 별도 목록에 있어 같은 주제의 정보를 모으기 어려웠다. 이제 기록에서 ‘폴더로 보기’를 누르면 글과 자료를 같은 폴더·하위 폴더에서 열 수 있다. LIFE와 WORK의 폴더는 각각 유지한다.

- 자료 작성·수정 화면의 ‘보관 폴더’에서 전체 경로를 선택한다. 폴더 안에서 새 자료를 만들면 그 위치를 기본으로 사용한다.
- 기존 자료는 자동으로 이동하지 않는다. 폴더가 지정되지 않았거나 사라진 자료는 ‘폴더 없음’과 전체 목록에 표시한다.
- 폴더 목록·왼쪽 트리·폴더 관리에서 자료도 함께 집계한다. 자료는 원본 `refs` 문서에 선택 필드 `fid`만 추가하며 글로 복제하지 않는다.
- 제목·본문 검색에 폴더 경로를 추가한다. 검색·프로젝트 연결에서 자료를 열면 해당 자료가 보관된 폴더에서 열리므로 다른 폴더를 보고 있던 상태에서도 찾을 수 있다.
- 폴더 탐색을 뒤로 가기 기록에 포함한다. 작은 화면에서는 트리 대신 본문의 폴더 목록과 상위 폴더 버튼을 사용한다.
- 모바일 목록에는 즐겨찾기와 복사를 유지하고, 삭제와 본문 링크는 자료를 연 뒤 사용한다.

## 데이터 보존

자료의 `fid`를 추가한 뒤에도 기존 저장 충돌 검사를 유지한다. 폴더만 바꾸면 다른 기기에서 수정한 본문은 덮어쓰지 않고, 본문만 바꾸면 다른 기기의 폴더 이동은 보존한다. 같은 자료의 폴더를 동시에 다르게 변경하면 기존 충돌 안내를 사용한다.

자료 생성 및 위치 변경 시 Firestore 트랜잭션으로 대상 폴더의 존재와 공간을 확인한다. 작성 중 폴더가 삭제되면 제목과 본문을 유지하고 위치를 다시 선택하도록 안내한다. 공간을 바꾸면 이전 공간의 폴더 선택을 해제한다. 임시 작성 내용 복구 시 새 폴더 선택도 복구하며, 폴더 필드가 없던 이전 버전의 임시 작성 내용은 기존 위치를 지우지 않는다.

폴더 삭제는 글·자료·하위 폴더를 상위 폴더로 이동하는 기존 원자적 일괄 처리에 자료를 포함한다. 삭제 실패 시 전부 유지한다. 되돌리기는 원래 위치를 복구하되 삭제 이후 사용자가 바꾼 위치를 덮어쓰지 않는 기존 규칙을 사용한다. 백업은 기존 `notes`, `refs` 전체 필드를 보존하므로 형식 변경이 없다.

## 검증

`tests/test_resource_folders.py`의 12개 UI 검증은 Firebase를 모의 구현으로 대체하며 실제 사용자 데이터에 접근하지 않는다. 혼합 폴더, 하위 폴더의 기본 위치, 기존 자료 분류, 폴더 경로 검색, 다른 폴더에서 검색해 열기, 다른 기기의 폴더·본문 편집, 이전 임시 작성 내용 복구, 공간 이동, 실패 후 재시도, 삭제된 위치, 폴더 삭제와 되돌리기, 320/390/768/1365px 화면과 키보드 조작을 확인한다.

전체 회귀 검사 `python3 -m unittest discover -s tests -v`: 324개 통과. 추가 화면 점검에서 `/Arecmik/` 경로의 320~1920px 홈·프로젝트·기록 화면에 가로 넘침이 없고, 탐색만으로 기록을 변경하지 않으며, 재생성한 미리보기가 실제 데이터와 분리되어 새로고침 시 초기화됨을 확인했다.

일반 PDF·엑셀·워드 파일 업로드, 폴더의 드래그 이동, 작성하지 않은 할 일의 기록 전환은 이 변경에 포함하지 않는다. 기존 자료와 직접 쓴 글의 정리 위치를 연결하는 변경이다.
