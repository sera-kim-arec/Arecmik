# 저장 안전성 개선 — 2026.10.22.10

## 범위

사용자가 승인한 안정성 개선의 첫 단계다. 기존 화면 배치와 무료 GitHub Pages / Firebase 구성을 유지한다. 서버·유료 서비스·Cloud Functions를 추가하지 않는다. 이전 버전 이력과 복원은 사용자 요청에 따라 제외했다.

## 달라진 동작

- 글의 제목·본문, 프로젝트 이름·핵심 메모·진행 기록, 홈의 잊지 말 것, 일지·일기에 편집 시작 시점의 내용을 보관한다. 입력 이후의 실시간 스냅샷을 편집 기준으로 착각하지 않는다.
- 자동저장 시 Firestore 트랜잭션에서 변경할 필드의 기준과 현재 서버 값을 비교한다. 다른 기기에서 같은 필드를 고쳤으면 서버를 덮어쓰지 않고 임시 편집을 유지한다. 즐겨찾기나 연결처럼 수정하지 않은 필드의 변경은 보존한다.
- 할 일·일정, 기록, 자료, 비용의 수정창도 기준 내용을 보관한다. 사용자가 실제 바꾼 필드만 저장하므로 메모를 쓰는 동안 다른 기기에서 바꾼 제목·날짜·완료 상태를 원래 값으로 되돌리지 않는다.
- 충돌 시 내 편집과 저장 시 확인한 서버 내용을 표시한다. ‘내 수정으로 저장’을 선택해도 표시한 서버 내용을 기준으로 다시 비교한다. 그 사이 또 바뀌면 다시 중단한다. 새 글로 따로 보관하는 방법도 제공하며, 작성창의 날짜·하위 할 일 등은 글 안에 함께 남긴다.
- 삭제된 일반 문서를 자동으로 다시 만들지 않는다. 서버에서 삭제됐음을 알리고 새 글로 보관할 수 있다.
- 일지는 해당 날짜만 비교하고 최신 월 문서의 나머지 날짜를 유지한다. 알려진 월별·일별 중복본의 같은 날짜는 하나의 트랜잭션에서 함께 갱신한다. 새 월 문서에는 공간·월별 고정 ID를 사용해 새 버전의 두 기기가 첫 월을 중복 생성하는 것을 막는다.
- 실패한 자동저장은 ‘다시 저장’으로 재전송한다. 일시적 장애는 5 / 15 / 60초 간격으로 최대 세 번 추가 시도하며, 연결 회복과 앱 재실행 시에도 재검사한다. 권한·한도 오류와 충돌은 자동 반복하지 않는다. 저장 버튼이 있는 창은 입력을 보관하고 직접 다시 저장한다.
- 저장 중 이어 쓴 내용은 이전 전송의 성공으로 삭제하지 않는다. 이미 저장한 필드만 기준을 갱신하며, 아직 보내지 않은 필드의 충돌 기준은 유지한다. 계정이 바뀌면 이전 계정의 재시도와 UI 갱신을 중단한다.
- 이전 앱 버전이 남긴 기준 정보 없는 임시 편집은 자동 재전송하지 않는다. 직접 다시 저장을 눌러도 비교·선택 없이 덮어쓰지 않는다.

## 구현

- `safe-save.js`: 필드 비교와 충돌 오류, 일시적 장애 분류.
- `index.html`: 화면을 그릴 때 기준 캡처, 트랜잭션 저장, 계정별 임시 편집과 재시도, 일지 날짜별 갱신, 작성창 변경 필드 추출과 충돌 선택.
- `app-ux.css`: 실패·충돌일 때만 나타나는 안내 및 비교 화면.
- `tests/firebase_mock.js`: 트랜잭션 읽기 이후 변경도 감지하고 콜백을 재시도하도록 테스트 어댑터 보완.

Firestore의 기존 읽기·쓰기 한도를 사용한다. 편집 저장에 비교용 읽기가 추가되며 유료 플랜 변경은 필요하지 않다. 기존 데이터를 일괄 변환하는 작업은 없다.

- Chromium에서 실제 작성·저장 UI와 모의 Firebase로 동시 수정, 트랜잭션 도중 원격 변경, 실패·재시도, 새로고침, 삭제, 계정 전환을 검사한다.
- PC 및 320 / 390px 모바일 폭에서 충돌 안내·비교·저장 버튼의 잘림과 가로 넘침을 확인한다.
- 기존 전체 회귀 검사와 경로 접두사 `/Arecmik/`, 독립 미리보기 검사를 수행한다. 최종 결과는 아래에 기록한다.
- 개인 운영 데이터는 읽거나 바꾸지 않았다. 운영 보안 규칙과 실제 두 기기 로그인을 사용하는 검증, 실제 Android 키보드·절전·백그라운드 동작은 별도 실기 확인 대상이다.
- 이 보호는 새 버전의 저장 경로에 적용된다. 업데이트 후 PC 탭과 Android 앱을 다시 열어 새 코드를 사용해야 한다. 실시간 공동 편집이나 이전 버전 보관 기능은 아니다.
- 기기에만 남은 편집은 브라우저 저장 공간 삭제·기기 손실까지 보호하지 않는다. 네트워크가 없는 상태의 최초 실행을 추가로 지원하지 않는다.
