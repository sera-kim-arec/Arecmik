# 하위 폴더 계층 표시 · 2026.10.23.12

자료실의 폴더 목록은 전체 경로를 같은 깊이로 나열해 부모·자식 관계가 시각적으로 드러나지 않았다. 기존 부모 ID를 사용해 표시만 계층 구조로 바꾼다.

- PC 폴더 목록을 중첩 목록으로 만들고 들여쓰기·연결선·별도 펼치기 버튼을 제공한다. 폴더 이름은 자기 이름만 표시하며, 전체 위치는 툴팁과 현재 경로에서 확인한다.
- 펼치기는 `aria-expanded`와 `aria-controls`를 갱신하고 해당 자식 목록만 접는다. 현재 폴더·검색·자료 목록은 바꾸지 않고 포커스도 유지한다. 폴더 선택은 부모 경로를 펼친 뒤 이동한다.
- 자료 영역 위에 현재 경로와 바로 아래 폴더를 표시한다. 경로의 부모를 누르거나 하위 폴더를 눌러 이동하고 뒤로 가기로 이전 폴더로 돌아온다.
- 모바일 폴더 선택은 부모→자식 순서와 들여쓰기를 사용한다. 같은 이름의 하위 폴더가 있어도 부모와 현재 경로로 구별한다. 바로 아래 폴더 버튼은 44px 이상으로 제공한다.
- 부모 폴더가 하위 자료까지 찾는 범위, 기록·자료실 구분, 기존 원본·폴더 ID·작성 위치·저장·삭제/되돌리기는 유지한다. 홈·프로젝트 배치는 변경하지 않는다.
- 계층 계산은 고아 폴더와 순환 부모 관계에 방문 가드를 사용하며 저장된 부모를 자동 수정하지 않는다.

## 검증

로컬 실제 앱을 Chromium으로 열고 Firebase만 메모리 어댑터로 대체했다. 실제 사용자 데이터에는 접속하지 않는다.

- 신규 계층 테스트5개:3단계 들여쓰기와 펼치기, 선택한 자식의 부모 접기, 경로·하위 폴더 이동과 Back,320/390px 선택 순서·터치 크기·넘침, 하위 폴더 생성 시 부모와 원본 보존.
- 신규5개와 기존 자료실·용도 구분 묶음26개 통과.
- 공통 폴더·자료 작성·공통 편집기·컨테이너 묶음39개 통과.
- PC1365px와 모바일390px 화면을 캡처해 계층과 경로 배치를 확인했다. 모듈 문법과 diff 공백 검사도 통과했다. 전체 저장소 테스트를 모두 실행한 결과는 아니다.
