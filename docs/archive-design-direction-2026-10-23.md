# 기록과 자료실의 화면 방향

눌러 볼 수 있는 예시: [`archive-design-preview.html`](../archive-design-preview.html)

이 미리보기는 예시 데이터와 메모리 안의 임시 작성 내용만 사용한다. 실제 앱의 Firebase, 로그인, 로컬 저장소, 서비스 워커에 접근하지 않는다. 검색, 공간·종류·폴더 선택, 즐겨찾기, 상세 읽기, 관련 자료 열기, 예시 작성·수정·저장, 작성 중 내용 이어 쓰기를 확인할 수 있다. 새로고침하면 초기화된다.

## 현재 화면에서 해결할 문제

현재 기록의 분류에는 목적에 따른 ‘자료실’과 작성 형식에 따른 ‘메모·기록 / 일기 / 글’이 같은 수준에 있다. 폴더로 들어가면 다시 ‘글·자료’를 함께 보게 된다. 같은 내용이라도 어느 작성 버튼으로 만들었는지에 따라 찾는 위치가 달라 보인다.

큰 입구는 두 개로 둔다.

- **나의 기록 / 업무 기록:** 내가 겪고 생각하고 결정한 것을 돌아보는 곳.
- **자료실:** 필요할 때 꺼내 쓰는 설명·문장·스크랩·링크를 모으는 곳.

홈·프로젝트·기록이라는 앱의 큰 이동 구조와 WORK/LIFE 구분은 유지한다. 이 미리보기는 그중 기록 영역의 배치를 보여 준다.

## 화면별 중심

### 기록

LIFE는 전체·일상·독서·영화로 모아 본다. WORK는 업무일지와 메모를 빠르게 찾는다. 일상 기록과 감상 글이 같은 작성창을 사용하고, 종류는 선택 사항으로 둔다. 저자·감독·별점·표지를 필수로 요구하지 않는다.

첫 화면에는 제목, 한 줄 내용, 종류, 날짜를 표시한다. 작은 책등 모양과 절제된 종류별 색으로 구분하되 큰 표지 카드로 목록의 밀도를 낮추지 않는다. 기록을 읽을 때는 본문을 넓게 펼친다.

### 자료실

검색 → 자주 꺼내 보는 자료 → 최근 보관한 자료 순서로 배치한다. PC의 왼쪽에는 폴더·하위 폴더를, 모바일에는 폴더 선택을 둔다. 폴더 계층을 여러 화면에 반복해서 표시하지 않는다. 상위 폴더를 고르면 하위 폴더의 자료도 찾는다.

자료를 보관할 때 제목과 내용·링크로 시작한다. 폴더 지정은 나중에 할 수 있게 한다. 폴더가 없는 자료도 검색·전체 목록에 남는다. 빈 검색 결과에는 조건을 지우는 행동과 새 자료 보관을 제공한다.

목록의 연결 버튼은 없애고, 상세 화면 아래에 필요한 관련 기록·자료만 둔다. 같은 책의 감상에서 인용문 자료를 열고 다시 돌아오는 흐름을 유지한다.

## 디자인 규칙

- 따뜻한 크림 배경과 흰 본문, 레몬색 선택 표시를 사용한다. 기존 레몬 마크를 재사용한다.
- PC에서는 탐색과 본문을 나누고, 모바일에서는 두 개의 큰 입구와 짧은 필터 줄로 바꾼다.
- 목록과 상세 화면의 제목·내용·부가 정보 크기를 구분한다. 버튼·색·설명 문장을 항목마다 반복하지 않는다.
- 모바일의 핵심 조작은 최소 44px 높이로 둔다. 전체 목록은 한 줄씩 편하게 누르며, 즐겨찾기는 별도 버튼으로 둔다.
- 작성할 때는 본문을 먼저 쓰고, 분류와 보관 위치는 접어서 둔다. 실수로 닫아도 작성 중 내용을 이어 쓴다.

## 실제 앱에 옮길 구현 순서

1. **탐색 통합:** 지금의 기록 검색·목록을 재사용해 작성 방식과 무관하게 읽고 찾는다. 일지·긴 글 등의 기존 편집기는 상세 화면에서 이어 쓴다. 전체 찾기는 기존처럼 현재 공간의 기록·자료·할 일을 함께 검색한다.
2. **용도와 저장 형식 분리:** 기존 원본은 유지하고 선택 메타데이터로 기록/자료 용도를 구분한다. 기본값은 현재 기록·자료 분류를 따른다. 기존 긴 글을 자료로 재분류할 때도 원본을 복제하거나 다른 컬렉션으로 옮기지 않아 연결과 편집 내용이 유지되게 한다.
3. **쓰기 흐름 정리:** 선택한 종류·폴더를 새 항목의 기본 위치로 사용한다. 쓰던 임시 내용이 있으면 그 선택을 우선한다. 기존 트랜잭션 충돌 검사와 임시 저장을 계속 사용한다.
4. **검증 후 적용:** 기존 항목·관련 항목 열기, 분류 변경, 검색, 폴더 삭제·되돌리기, PC/모바일 뒤로 가기를 확인한다. 시각 변경 때문에 저장 로직이나 블록 편집기를 다시 작성하지 않는다.

이 방향은 기존 무료 정적 호스팅과 Firebase 구조에서 구현할 수 있다. 별도의 검색 서버나 외부 유료 서비스를 전제로 하지 않는다. 미리보기의 간단한 텍스트 작성창은 배치 확인용이며, 실제 앱에 적용할 때는 기존 블록 편집기를 사용한다. 일반 파일 업로드 기능은 이 미리보기에 포함하지 않는다.

## 미리보기 검증

JavaScript 구문 검사와 브라우저에서 검색·WORK/LIFE 분리·상위 폴더 조회·즐겨찾기·관련 항목 열기와 수정·입력 검증·임시 작성 이어 쓰기·예시 저장·Escape와 브라우저 뒤로 가기를 확인했다. 320/390/1365px에서 기록·자료실·작성창의 가로 넘침을 확인했다. 실제 앱의 로컬 저장소와 모의 데이터베이스가 유지되고, 미리보기 자체에서는 외부 요청이 발생하지 않으며, 새로고침하면 예시 작성 내용이 초기화됨을 확인했다.
