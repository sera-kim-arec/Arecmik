# 기록과 자료실 적용 · 2026.10.23.8

별도 예시 화면이 아닌 실제 앱의 기록 탭에 적용한다. 홈·프로젝트·기록의 큰 이동 구조와 WORK/LIFE 공간은 유지한다.

## 화면과 동작

- 큰 입구는 LIFE의 ‘나의 기록’, WORK의 ‘업무 기록’과 ‘자료실’이다. 기록은 날짜별로, 자료실은 즐겨찾기 자료와 최근 보관한 자료로 모은다. 오래된 즐겨찾기도 첫 페이지 앞에 표시하며 중복하지 않는다.
- 자료실의 PC 왼쪽 폴더와 모바일 폴더 선택은 같은 상태를 사용한다. 부모 폴더는 하위 폴더 자료도 포함하며, 폴더 없는 자료와 공간 없는 기존 WORK 자료도 찾을 수 있다.
- 목록 검색·즐겨찾기는 선택한 용도 안에서 동작한다. 전체 찾기는 기존처럼 현재 공간의 모든 종류를 검색한다. 빈 목록에는 조건 지우기·작성, 빈 검색에는 전체 찾기 탈출구를 제공한다.
- 달력·할 일은 기본 기록 목록에 누적하지 않는다. 기존 조회는 접힌 작성 방식 필터와 전체 검색에 남긴다.
- 자료 작성은 제목·본문을 먼저 두고 공간·용도·폴더를 아래에 둔다. 제목이 없으면 본문 첫 줄을 사용한다. 폴더는 선택 사항이며 선택한 폴더를 새 자료와 긴 글의 기본 위치로 사용한다.
- 자료 상세를 닫을 때 목록 검색과 폴더가 유지된다. 폴더·용도 이동과 글 읽기는 기존 브라우저/Android 뒤로 가기 상태와 함께 동작한다.
- 기존 레몬·크림 테마를 유지하고 작은 책등 표시와 짧은 요약으로 목록을 정리했다. 320/390/768/1365px에서 가로 넘침과 주요 조작의 44px 높이를 확인한다.

## 원본과 저장

긴 글(`notes`)과 자료 메모(`refs`)에 선택 필드 `archivePurpose`를 사용한다. 유효한 값은 `record`와 `resource`다. 필드가 없는 원본은 긴 글=기록, 자료=자료실로 표시한다. 일지·진행 기록 등은 계속 기록에 남는다. 자동 추측이나 일괄 데이터 이동은 하지 않는다.

용도를 바꿔도 컬렉션과 ID는 유지한다. 기존 HTML·사진·프로젝트·공통 연결·즐겨찾기 필드를 다시 만들지 않는다. 글의 용도는 기존 필드별 자동저장·충돌 검사·로컬 복구에, 자료의 용도는 기존 작성창 트랜잭션·임시 작성에 포함한다. 이전 작성창 임시 데이터에 용도 필드가 없으면 원격 분류를 덮어쓰지 않는다.

폴더 생성·자료의 폴더 유효성 검사·폴더 삭제와 원자적 재배치·되돌리기는 기존 경로를 재사용한다. 자료실에서 폴더를 만들면 새 탐색 화면의 해당 폴더에 남는다. 기존의 글·자료 통합 폴더 화면도 ‘폴더로 보기’에서 이용할 수 있다.

추가 서버·검색 서비스·유료 의존성은 없다. 기존 Firebase와 정적 호스팅을 사용한다. 임의 PDF/오피스 파일 업로드나 새로운 노션 동기화는 이번 범위에 포함하지 않는다.

## 검증

Firebase 메모리 어댑터로 실제 앱을 Chromium에서 실행한다. 실제 사용자 계정·저장 데이터에 접근하지 않는다.

- 신규 `test_archive_library.py`: 원본 재분류·관계 보존, 기록/자료실 검색과 즐겨찾기 범위, 부모 폴더 포함, 오래된 즐겨찾기 페이지 배치, 자료 읽기·뒤로 가기, 본문 첫 줄 제목·선택 폴더, 기존 블록 편집기로 새 자료 글 작성, 저장 실패와 임시 작성 복구, 원격 필드 보존·동시 분류 충돌·이전 임시 작성, 즉시 폴더 생성, 반응형 조작을 검증한다.
- 기존 LIFE 분류·공통 폴더·기록 생성·저장 안전성 및 화면/연결/즐겨찾기 회귀 테스트를 실행한다. 기존 테스트의 탐색 보조 함수는 접힌 작성 방식 필터를 실제 사용자처럼 펼친다. 검색과 즐겨찾기의 기대값은 새로운 용도 범위에 맞춘다.
- 모듈 구문 검사, 생성 미리보기 동기화, `git diff --check`를 실행한다.

관련 최종 실행은 신규 자료실·공통 폴더 25개, 화면·연결·즐겨찾기·WORK 43개, 일정 상세·UX 흐름 21개, LIFE 분류 9개, 저장 안전성 27개, 원래 기록 7개로 총 132개 통과했다. 전체 회귀 실행 중 기존의 ‘기록 목록 검색이 자료·할 일까지 함께 찾는다’, ‘즐겨찾기가 용도와 무관하게 한곳에 모인다’는 기대값과 접힌 필터를 건너뛰던 탐색 도우미가 실패하여 새 범위에 맞게 수정했다. 관련 검사는 수정 후 다시 실행했다. 수정 전 전체 실행을 전체 통과로 계산하지 않는다.

실제 계정의 기기 간 동기화와 Android 실기기 조작은 브라우저 모의 테스트의 범위 밖이다.
