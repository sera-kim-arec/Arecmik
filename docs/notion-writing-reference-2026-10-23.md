# 영상 기준 글쓰기 동작 개선

버전: `2026.10.23.4`. 사용자가 제공한 약 80초의 Notion 글쓰기 영상을 기준으로 했다. 개인 영상과 캡처는 저장소에 포함하지 않는다.

## 관찰과 반영

| 영상에서 확인한 흐름 | 앱의 처리 |
| --- | --- |
| 새 문단은 여유가 있고 같은 문단의 줄바꿈은 붙어서 이어짐 | Enter는 별도 문단, Shift+Enter는 문단 안의 `<br>`. 일반 문단의 간격과 문단 안 줄 간격을 구분한다. |
| 토글 안에서 여러 줄을 쓰고, 내용 뒤 빈 줄에서 Backspace로 밖에 작성 | 토글의 마지막 빈 문단에 앞선 본문이 있으면 한 단계 밖으로 옮긴다. 기존 본문은 안에 유지한다. |
| 인용문에 두 줄을 넣고 일반 문단으로 이어 씀 | 메뉴에서 인용문 생성, Shift+Enter로 같은 인용선 안에 이어 쓰기, 끝에서 Enter로 일반 문단. 저장·재열기로 확인한다. |
| 약 27~30초: 마우스로 손잡이를 잡아 문단을 위로 옮기고 문단 전체가 선택됨 | 왼쪽 여백에서도 클릭 없이 해당 줄의 도구를 표시한다. 실제 드롭 위치를 표시하고, 드롭 뒤 해당 블록을 선택한다. 도구 밖으로 마우스를 옮기면 도구는 숨긴다. |
| 약 40~44초: 토글을 만든 뒤 제목을 쓰고 화살표로 본문을 펼침 | 메뉴로 만든 토글은 처음에 접힌 상태다. 새 빈 토글을 펼치면 본문에 바로 쓸 수 있다. 내용이 이미 있는 토글을 펼칠 때는 입력 위치를 바꾸지 않는다. 제목에서 Enter로도 본문을 열고 작성한다. |

영상에서 새 문단의 글자 위치 차이는 약 40px, 같은 문단의 줄 간격은 약 24px다. 편집기는 16px 글씨, 24px 줄 간격으로 맞췄다. `+`와 손잡이는 글꼴에 따라 모양이 달라지는 문자 대신 작은 더하기와 여섯 점 SVG로 표시한다. 토글의 첫 빈 본문은 커서가 있을 때만 작성 안내를 표시한다. 기존 글 사이의 빈 문단마다 안내가 반복되는 문제는 다시 만들지 않는다.

첫 번째 빈 토글 본문은 기존처럼 제목으로 돌아간다. 중간 빈 줄에서 Backspace를 누르면 뒤의 내용을 밖으로 옮기지 않는다. 중첩 토글에서는 해당 토글 한 단계만 빠져나온다. 빈 줄에 soft break가 들어 있으면 단순한 빈 블록으로 취급해 삭제하지 않는다.

PC Shift+Enter와 취소 가능한 모바일 `beforeinput: insertLineBreak`는 같은 명령을 사용한다. 한글 조합 중 입력과 취소할 수 없는 이벤트는 기존 편집기 처리에 맡긴다.

일반 문단의 스타일 표시는 ProseMirror의 화면용 decoration이다. 문단 클래스와 편집 도구는 저장된 HTML에 들어가지 않는다. 기존 글을 여는 것만으로 데이터를 변환하거나 저장하지 않는다. 노션 연결이나 저장소 변경, 앱의 탭 배치 변경은 포함하지 않는다.

## 검증

- `tests/test_notion_writing_flow.py`: 실제 키 입력, Enter와 Shift+Enter의 화면 간격 및 저장 구조, 마지막·중간 빈 줄의 Backspace, 중첩 순서, 실행 취소/다시 실행, 네이티브 입력 의도, 인용문과 저장 후 재열기.
- 같은 파일의 연속 시나리오: 영상의 글쓰기 → 손잡이 드래그 → `+`로 토글 추가 → 화살표로 빈 본문 열기 → 여러 줄 작성 → Backspace로 밖에 작성 → 인용 → 저장·재열기를 한 세션에서 실행한다. 포인터를 글 위로 먼저 옮기지 않고 왼쪽 여백에 진입하는 경우도 확인한다.
- 모의 Firebase를 사용하는 기존 전체 회귀 검사. 실제 개인 데이터를 읽거나 쓰지 않는다.
- PC 1365px와 모바일 390px에서 영상의 작성 흐름을 재현하고 화면을 확인한다.
- 320~1920px의 세 탭, 프로젝트 상세, `/Arecmik/` 경로 및 독립 미리보기를 확인한다.
- 실제 Gboard/Samsung Keyboard와 운영 계정에서의 검증은 별도 실기 확인 대상이다. 이 변경이 Notion의 모든 편집 기능을 제공한다는 의미는 아니다.

추가 화면 확인: PC 1365px와 모바일 390px에서 글, 잊지 말 것, 업무일지, 프로젝트 메모, 일정 메모, 기록, 자료의 7개 작성칸에 같은 순서로 입력한다. 자동/명시적 저장과 새로고침 후 토글·줄바꿈·인용 구조가 남는지, 화면용 도구가 저장 내용에 섞이지 않는지 확인한다.

최종 결과: 전체 **303개 검사 통과**. 7개 작성칸 × 2개 화면 폭의 입력·저장 확인, 320~1920px의 세 탭과 펼친 프로젝트, 경로 접두사·미리보기 분리 검사도 통과했다. JavaScript 문법 및 `git diff --check` 통과. 예시 데이터로 촬영한 약 14초의 시연 영상은 별도 작업 산출물로 남겼다.
