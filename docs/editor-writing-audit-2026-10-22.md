# 글 입력·삭제 점검 — 2026-10-22

대상: 웹 버전 `2026.10.22.9`. 실제 앱을 Chromium에서 열고 Firebase를 메모리 어댑터로 대체해 검사했다. 실제 계정이나 개인 기록은 읽거나 수정하지 않았다.

## 발견하고 수정한 문제

| 재현 조건 | 기존 동작 | 수정 후 |
| --- | --- | --- |
| 토글 앞 문단 끝에서 Delete 두 번 | 토글 전체가 선택되고 제목·본문이 함께 삭제됨 | 제목 안으로 커서를 옮긴 뒤 글자 삭제 |
| 토글 뒤 문단 시작에서 Backspace 두 번 | 토글 전체가 선택되고 숨긴 본문도 함께 삭제됨 | 마지막으로 보이는 본문 또는 제목으로 이동한 뒤 글자 삭제 |
| 토글 제목 끝에서 Delete 두 번 | 본문 컨테이너가 선택되고 본문 전체가 삭제됨 | 펼친 본문 또는 다음 보이는 글로 이동. 닫힌 본문은 유지 |
| 같은 달이 여러 문서에 나뉜 일지에서 날짜 내용 삭제 | 첫 번째 월 문서에 쓰려다 삭제가 반영되지 않거나 이전 내용이 다시 보임 | 해당 날짜를 가진 월 문서·기존 날짜별 문서를 함께 갱신하고 다른 날짜는 유지 |

Ctrl/Cmd를 함께 누른 삭제와 네이티브 `beforeinput` 삭제에도 토글 경계 처리를 적용했다. 전체 선택·삭제, 블록 메뉴 삭제 등 직접 선택한 내용의 삭제는 계속 가능하다.

같은 앱에서 같은 달의 서로 다른 날짜를 빠르게 편집하면 저장을 순서대로 처리한다. 같은 날짜의 중복 저장본은 하나의 배치로 갱신하고, 실패하면 원본은 유지하며 기존 임시 복구 안내를 사용한다. 앱을 여는 것만으로 저장본을 변환하지 않는다.

| 기록 탭의 업무일지·일기 | WORK / LIFE | 날짜별 자동저장 |

각 화면에서 키보드 입력 → 중간 줄 지우기 → 문단 합치기 → 전체 지우기 → 토글 작성 → 전체 지우기·되돌리기·다시 실행 → 저장·새로고침·재열기 → 빈 내용 저장을 검사한다. 기록 작성창은 빈 기록 저장을 막는 안내와 기존 원본 보존을 확인한다. 반대 공간의 기록도 바뀌지 않아야 한다.

추가 검사:

- 토글 앞뒤, 제목 끝, 닫힌 본문의 삭제 경계와 단어 삭제 단축키
- 실제 Chromium IME 조합·확정·조합 취소와 이어지는 삭제
- 숨긴 사진이 있는 글의 전체 삭제·실행 취소·재열기, 사진 ID 유지
- 날짜 삭제 시 같은 달의 다른 날짜 유지
- 월 문서 중복 + 기존 날짜별 문서가 함께 있을 때 삭제 반영
- 중복 저장본 갱신 실패의 원자성과 임시 복구 상태
- 저장이 느린 동안 두 날짜를 연속 편집해도 두 변경 내용 유지

## 결과

전체 브라우저 회귀 검사 **259개 통과**. 미리보기 격리·새로고침 초기화와 320~1920px 너비의 실제 탭·확장 프로젝트 화면도 확인했다.

## 검증 방법과 한계

새 회귀 검사는 `test_editor_surfaces.py`, `test_editor_delete_boundaries.py`, `test_journal_editing_integrity.py`에 있다. 기존 글·토글·사진·저장 실패·복구·화면 전환 검사도 전체 unittest 발견으로 함께 실행한다.

모바일 너비·터치 에뮬레이션과 브라우저 IME는 실제 Android 기기의 Gboard/Samsung Keyboard와 완전히 같지 않다. 실제 폰 키보드, 실제 Google 로그인, 실제 Firebase에서 두 기기가 같은 내용을 동시에 고치는 상황은 이번 자동 검사의 범위에 포함하지 않는다. 따라서 모든 기기와 입력 방식에서 오류가 없다고 보증하는 결과는 아니다.
