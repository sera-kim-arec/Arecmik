# 기록·자료실의 폴더 탐색 일치 · 2026.10.23.11

첫 목록은 보관 용도로 나뉘었지만 ‘폴더로 보기’와 상세 화면의 트리는 기존 notes/refs 전체를 다시 합쳐 표시했다. 폴더의 ‘글/자료’ 이름도 저장 컬렉션에 따라 달라져, 사용자가 자료로 분류한 글이 폴더에서는 글로 표시됐다.

- 기록/자료실의 제목, 폴더 목록·개수·행 표시, 상세 화면의 폴더 트리를 보관 용도에 맞춘다. 기록은 날짜별, 자료실은 주제 폴더·즐겨찾기 중심인 기존 첫 화면을 유지한다.
- 폴더를 열거나 전체 목록으로 돌아와도 해당 용도를 유지한다. 검색·홈·연결에서 연 글은 원본의 용도를 따른다. 글과 기존 자료 모두 현재 폴더의 상위 경로를 펼쳐 보여준다.
- 자료실 폴더와 상세 트리의 새 글은 자료로 저장한다. 트리의 ‘＋’는 보고 있던 문서가 아닌 실제 누른 폴더를 사용한다. 새 폴더를 만들고 돌아오는 경로도 현재 용도를 유지한다.
- 공통 글쓰기 양식과 원본 ID·본문·사진·프로젝트·연결을 그대로 사용한다. 용도나 폴더 선택 시 옆 목록과 위치만 갱신하고 활성 본문 편집기는 교체하지 않는다.
- 폴더의 자료 행은 notes/refs에 관계없이 같은 즐겨찾기·복사 동작을 제공한다. 행 안의 버튼은 문서를 여는 동작과 분리하고, 복사 실패를 성공으로 알리지 않는다.
- 홈의 자료 목록·개수·검색도 같은 보관 용도를 사용한다. 직접 작성한 자료를 포함하고, 기록으로 바꾼 기존 자료는 제외한다. ‘전체’는 자료실 첫 화면으로 이어지며 홈의 배치는 유지한다.
- refs의 프로젝트 배정도 기록/자료실 목록의 프로젝트 검색·필터에 반영한다.

별도 정리함, 새로운 분류 필수값, 컬렉션 복사·이전, 서버 추가는 없다. 폴더 구조와 관리 기능은 공유하며, 관리·삭제 확인은 두 용도의 내용을 함께 안내한다. 보관 용도 없는 기존 글은 기록, 기존 자료는 자료실로 계속 표시한다. 사용자가 정하지 않은 용도를 자동 추측하지 않는다. 홈·달력·프로젝트 배치는 변경하지 않는다.

## 검증

테스트는 로컬 실제 앱을 Chromium에서 열고 Firebase만 메모리 어댑터로 대체한다. 실제 계정이나 사용자 데이터에 접속하지 않는다. 
- 신규 용도 탐색 8개 통과: 뒤바뀐 저장 형식(notes 자료/refs 기록), 두 모드·중첩 폴더·상세 트리, 검색 진입, 폴더에서 작성, 원본 유지 재분류, 320/390px·키보드, 즐겨찾기·복사와 같은 ID, 홈 자료 검색·빈 결과·작성.
- 공통 양식·폴더·연결·자료 작성 묶음 53개 통과. 연결 검사의 진입 도우미는 현재 보관 용도에 의존하지 않고 기록 모드를 명시적으로 선택하도록 수정했다.
- 홈 배치·업무·공통 양식 최종 묶음 31개 통과. 자료실·LIFE·기록 묶음 29개 통과. 초기 관련 회귀에서 저장 안전성 27개와 컨테이너 7개도 통과했다. 전체 저장소 테스트를 한 번에 모두 실행한 결과는 아니다.
- WORK의 기록·자료실 PC 화면, 자료 폴더·상세의 PC/390px 화면을 캡처해 확인했다. 원격 실제 기기·Firebase 로그인·기기 간 동기화 검증은 포함하지 않는다.
